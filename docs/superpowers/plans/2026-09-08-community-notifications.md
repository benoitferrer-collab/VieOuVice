# Catalogue communautaire et notifications web — plan

Objectif : chacun crée un écart/bonne action avec ses valeurs fictives, réutilisable par tous ; notifications d’amis/duels dans le jeu et Web Push avec consentement.

Contraintes : préserver Next.js/Supabase et données existantes. Aucune clé secrète Supabase partagée précédemment n’est utilisée. Pas de migration distante via l’agent ; produire des mises à jour non destructives à exécuter dans SQL Editor. Pas de publication. Installation cloud Web Push documentée si aucun serveur public disponible. Les anciennes versions SQL initiales restent immuables ; nouvelles migrations 002 puis 003.

Décisions de conception : catalogue immédiat authentifié, créations immuables (nouvelles variantes pour changer une valeur), libellé 3–60, unité 2–40, magnitude 1–120 min, quantité max 1–10, cinq créations/jour. Bonnes actions communautaires : plafond par catégorie 120 et plafond GLOBAL 150 min/jour pour éviter de multiplier les catégories pour contourner les limites. Scores hebdomadaires incluent impacts confirmés. Partage aux amis désactivé par défaut ; réception amis/duels activée mais désactivable séparément. Push demande de consentement volontaire ; aucun détail privé en push. Notification friend_action coalescée par auteur/destinataire/heure, duels au démarrage/changement de leader/clôture, pas d’auto-notifications sociales. Blocages et retrait du partage interdisent futures diffusions et invalident les push en attente concernés.

1. SQL migration 002 : community_catalog, create_catalog_action RPC idempotente, plafonds record_action, événements durables sociaux et settings dédiés. Tests SQL fournis ; pas exécutés cloud.
2. Push migration 003 et route : subscriptions privées, outbox dédupliquée, leases/retries bornés, RPC admin seulement, worker authentifié serveur, VAPID, service worker et composant consentement. Fonctions callable user sous RLS/RPC avec auth.uid; endpoint push whitelisted (SSRF) ; abonnements 410 supprimés. Aucun expéditeur depuis le navigateur.
3. UI + contrats : ajout/recherche/filtres catalogue officiel/communauté, création/confirmation/réutilisation et Démo. Réglages de partage/réception, cloche compteur, notification cliquable vers écran, toast Realtime sans rejouer toute la boîte à chaque reconnexion.
4. Validation et livraison : tests comportement, typecheck/lint/build, revue indépendante, guide mises à jour SQL/keys/push, rapport honnête sur contrôles cloud non exécutés.

Interfaces : CatalogItem ajoute creator_id nullable, creator_name nullable, created_at nullable. RPC create_catalog_action(p_label text,p_kind text,p_unit text,p_magnitude int,p_max_quantity int,p_idempotency_key uuid) retourne CatalogItem JSON. get_game_state ajoute community_enabled:true et social_settings:{share_activity,notify_friends,notify_duels}. RPC update_notification_settings(p_share_activity bool,p_notify_friends bool,p_notify_duels bool). Notice ajoute kind, actor_id nullable, target_tab, event_key nullable. Public notifications INSERT est autorité des pushes, trigger outbox seulement types sociaux. Push agent fournit composant WebPushSettings({demo:boolean}), export default/named documenté, indépendant de GameState.
